# Portable calculation bundles

Examples in this chapter that use `samples/` or `tests/data/` require a cloned
repository and should be run from its root. Release binaries do not include
those files; the [first-calculation guide](../getting-started/first-calculation.md)
shows how to create local inputs and obtain a basis.
Commands using `rustiq` assume the executable is installed or available on
`PATH`. From a source checkout without installation, use the
`cargo run --locked --` prefix described in the
[CLI reference](../reference/cli.md).

A `.rustiq` bundle is a portable snapshot of RustiQ calculation inputs and
optional reusable atomic-orbital electron-repulsion integrals (AO ERIs). It
lets users rerun saved calculations or reuse compatible AO ERIs in new ones
without carrying a machine-local cache. CLI reruns always start a new SCF run;
the CLI does not save a Hartree–Fock wavefunction. The Rust API can additionally
store converged RHF/UHF orbitals and restore a solution for MP2 without repeating
SCF, as described below.

## Create and inspect a bundle

### Release binary

First follow the local-input workflow in the
[first-calculation guide](../getting-started/first-calculation.md). Use the
`calculation.toml` generated by `rustiq init` and its downloaded or imported
STO-3G basis; no additional basis setup is needed.
Choose a destination that does not already exist.

```sh
rustiq run calculation.toml --artifact h2.rustiq
rustiq artifact inspect h2.rustiq
rustiq artifact verify h2.rustiq
rustiq run h2.rustiq
```

> [!TIP]
> With an online-enabled build and network access,
> `rustiq run calculation.toml --artifact h2.rustiq --auto-download`
> fetches STO-3G if it is missing during bundle creation. Direct reruns of an
> existing bundle need no basis download.

### Source checkout

Alternatively, from a cloned repository, make the checked-in STO-3G basis
available, then run the H₂ sample and write a bundle to the current directory:

The runfile used here is the checked-in H₂ sample. Run these commands from the
repository root:

```toml
{{#include ../../../samples/h2/sto-3g/calculation.toml}}
```

```sh
cargo run --locked -- basis import tests/data/sto-3g.json
cargo run --locked -- run samples/h2/sto-3g/calculation.toml --artifact h2.rustiq
```

`--artifact` writes the current calculation collection as a new bundle,
independently of text or JSON result output. For a Nickel study, the bundle
contains one entry for each requested calculation.

Inspect a bundle without the original runfile, geometry file, or basis store:

```sh
rustiq artifact inspect h2.rustiq
rustiq artifact inspect h2.rustiq --format json
```

Inspection displays canonical requested and resolved calculation snapshots,
producer information, artifact representations, and captured source names and
sizes. Requested values may differ from resolved values: for example, an
`Auto` HF method can resolve to RHF, and requested Angstrom coordinates appear
as resolved Bohr coordinates. Text output syntax-highlights the canonical TOML
and XYZ when color is enabled by `--color` or `RUSTIQ_COLOR`; use
`--color never` for plain text. The optional JSON `payloads_verified` field is
`false`: inspection validates the archive index, provenance, scientific
snapshots and declared artifact sizes, but does not hash or decode numerical
payloads. Use `artifact verify` to check supported payloads eagerly; otherwise,
execution checks a payload when its scientific stage selects and reads it.
Inspection is structural, not a calculation or an independent scientific
validation.

Use `artifact verify` to eagerly read and validate every supported numerical
payload in the bundle:

```sh
rustiq artifact verify h2.rustiq
```

The command verifies supported `ao_eri` and `converged_hf` artifacts through
their artifact readers. AO ERI checks cover payload hashes, NPY encoding, dimensions,
and consistency with the declared AO basis. HF checks cover metadata, referenced
payload integrity, array shapes, occupations, finite values, and context identity.
HF verification supports the `rustiq-converged-hf-orbitals-v1` representation.

The summary on stdout counts calculations and logical artifacts, rather than
individual files. Diagnostics go to stderr. For the H₂ bundle created above:

```text
Verification successful
  Calculations: 1
  Verified:     1
  Failed:       0
  Skipped:      0
```

The first line distinguishes three outcomes:

| Status | Meaning |
| --- | --- |
| `Verification successful` | Every declared artifact passed; none failed or were skipped. |
| `Verification incomplete` | No supported artifact failed, but at least one artifact was skipped. |
| `Verification failed` | At least one supported artifact failed, regardless of skips. |

Unknown artifact names and known artifacts with unsupported representations are
skipped with warnings. Their payloads are **not checked**: an older reader's
inability to interpret a representation is not evidence of corruption. Supported
artifacts with invalid metadata or payloads fail verification. Independent
failures are collected and reported together, with a summary after traversal.
A fatal archive error that prevents opening or traversal can stop without a summary.
Calculation indices in diagnostics are zero-based.

By default, exit code `0` means all supported artifacts passed; unsupported
artifacts may still have been skipped. Use `rustiq artifact verify PATH --strict`
to require exhaustive verification: skips without failures return `5`, reported
as a warning rather than evidence of corruption. Any supported artifact failure
or fatal archive error returns `1` in either mode. Failures take precedence over
skips. Strict mode returns `0` when every artifact passes.

A bundle without numerical artifacts returns `0` in either mode, with all three
artifact counters at zero and an explicit message:
`No numerical artifacts declared; no numerical payload was verified.`

Verification does not run the calculation or independently establish scientific
correctness, physical validity, orbital orthonormality, or adequacy of the method
and basis. Successful verification means the supported stored data passed its
reader's integrity and validation checks.

## Rerun a saved calculation

Run a `.rustiq` bundle directly to reconstruct and execute its archived
calculation settings, without the original runfile, geometry file, or basis
store:

```sh
rustiq run h2.rustiq
rustiq run h2.rustiq --format json --pretty --color never
```

For a multi-calculation bundle, RustiQ reruns every entry in manifest order and
reports a batch, like a multi-entry Nickel study. This is a fresh calculation:
RustiQ restores the resolved scientific inputs and reuses compatible AO ERIs
when present; otherwise it recomputes them. A corrupt compatible AO ERI payload
causes an execution error. It then runs HF again and MP2 again when requested.
It does not restore orbitals,
density matrices, DIIS history, or prior results, so this command does not
resume an SCF trajectory. A saved random seed is restored as an input; it does
not guarantee bitwise-identical results across software versions or platforms.

To use different settings, supply a TOML or Nickel input and use `--reuse`
instead. A direct archive rerun cannot be combined with `--reuse`, `--artifact`,
`--cache-dir`, `--auto-download`, or `--no-auto-download`.
With `--format json`, the rerun uses the normal single-calculation or batch
result schema and omits the `artifacts` reuse-decision array because the bundle
is the implicit artifact source. The source bundle remains unchanged; direct
reruns do not use the local AO ERI cache or download basis sets.

## Reuse AO ERIs in a new calculation

This workflow needs a TOML or Nickel input, its geometry, and an available
basis. `--reuse` does not run the calculation saved in the bundle or restore its
captured source files. Instead, RustiQ prepares the supplied input, checks the
bundle for compatible AO ERIs, and runs HF again; it also runs MP2 again if the
new input requests MP2. The archive itself supplies reusable artifacts and
remains read-only.

For the release-binary workflow, use the local `calculation.toml` created in
the first-calculation guide. Keep its downloaded basis available for this new
run; its geometry path resolves beside `calculation.toml`:

```sh
rustiq run calculation.toml --reuse h2.rustiq --format json --pretty --color never
```

From a source checkout, the equivalent command uses the checked-in sample:

```sh
cargo run --locked -- run samples/h2/sto-3g/calculation.toml --reuse h2.rustiq --format json --pretty --color never
```

When a runfile is executed with `--reuse` or `--artifact`, its JSON result
includes an `artifacts` entry. A reused AO ERI is reported like this:

```json
{
  "artifacts": [
    {
      "name": "ao_eri",
      "decision": "reused",
      "origin": "archive",
      "source_index": 0
    }
  ]
}
```

`decision` says whether the bundle supplied a compatible artifact; the CLI
reports `reused`, `missing`, or `incompatible`. `origin` says where the ERIs
actually came from: `archive`, an enabled local `cache`, or fresh `computation`.
For example, `decision: incompatible` with `origin: cache` means no bundle entry
matched but an enabled local cache supplied the ERIs. When an archive entry is
selected, `source_index` is its zero-based position in that bundle. In a batch,
each result reports its own selection.

The reuse order is:

1. First compatible AO ERI in the archive's manifest order.
2. Matching entry in the enabled local AO ERI cache.
3. Recompute the AO ERIs.

The local-cache step is used only when `[cache].enabled = true` in the runfile.
`--cache-dir` selects the cache location but does not enable caching; see the
[configuration guide](configuration.md#optional-local-ao-eri-cache) for the
input setting.

The archive remains read-only during reuse. To publish a new snapshot from the
calculation, provide a new destination. For the release-binary workflow:

```sh
rustiq run calculation.toml --reuse h2.rustiq --artifact h2-updated.rustiq
```

For a source checkout, use the sample path:

```sh
cargo run --locked -- run samples/h2/sto-3g/calculation.toml --reuse h2.rustiq --artifact h2-updated.rustiq
```

## What can be reused?

AO ERIs are reusable when the effective integral inputs match. RustiQ checks the
ordered atomic numbers and nuclear coordinates in Bohr, effective AO basis
functions, Schwarz screening setting, and integral representation and
computation versions. A
matching basis-set label or atom count alone is not enough. HF method and
convergence settings, and whether MP2 is requested, do not change AO ERI
compatibility. The [persistence specification](https://github.com/mveril/RustiQ/blob/main/docs/persistence-format-v1.md#scientific-identity-v1)
defines the complete identity.

| Change to the new input | AO ERI compatibility |
| --- | --- |
| HF method, initial guess, or SCF convergence limit | Can remain compatible; HF runs again with the new settings. |
| Add or change MP2 settings | Can remain compatible; MP2 runs again from the new HF result. |
| Geometry, effective AO basis, or Schwarz screening | Incompatible; RustiQ checks the local cache, then recomputes if needed. |

CLI-created bundles store scientific input snapshots and optional AO ERIs.
They do not yet capture converged HF orbitals. Save the result JSON separately
when reported results matter. Neither API stores density matrices, DIIS history,
or MP2 results.
Captured input and geometry bytes are provenance for inspection; they do not
affect compatibility, and Nickel imports are not captured recursively.
The same reconstruction is available to Rust callers; see the Rust API
examples in the [persistence specification](https://github.com/mveril/RustiQ/blob/main/docs/persistence-format-v1.md#single-calculation-execution-apis).

## Converged HF orbitals through Rust

The library exposes `ConvergedHfArtifact` through `RustiQData::set` and `get`.
`ConvergedHf::from_solution(&solution)` copies orbital data from a converged
`AnyHfSolution`, retaining its originating calculation identity and no AO ERIs.
The entry created by `RustiQData::from_calculation(&prepared)` must match that
identity. `RustiQBundle` reads and writes these entries alongside existing AO ERIs;
older V1 archives without HF remain readable.

As with AO ERIs, `set::<ConvergedHfArtifact>(&value)` stages the artifact on disk
immediately. Cloning an entry shares its stored payloads; replacing the artifact
in one clone does not affect the others. Each `get::<ConvergedHfArtifact>()` reads
and validates the payload again and returns an independently owned value.
`ArtifactRef::new::<ConvergedHfArtifact>(&value)` also supports direct borrowed
publication without staging. Republishing stored HF data streams its NPY files
without retaining decoded orbital arrays.

The only supported HF representation label is `rustiq-converged-hf-orbitals-v1`.

Orbital arrays are stored as NumPy-compatible NPY files. For RHF, each
calculation entry contains:

```text
orbitals/
├── converged-hf.json
├── coefficients.npy
└── energies.npy
```

For UHF, the two spin channels have separate directories:

```text
orbitals/
├── converged-hf.json
├── coefficients/
│   ├── alpha.npy
│   └── beta.npy
└── energies/
    ├── alpha.npy
    └── beta.npy
```

These paths are relative to `calculations/<id>/` inside the bundle, alongside
`calculation.json`, `request.json`, and optional `arrays/integrals/ao-eri.npy`.
`persistence::validate_matching_npy_shapes(alpha_reader, beta_reader)` compares
the ranks and axis lengths in two NPY headers before loading values. This
header-only check does not validate dtype, values, or payload integrity.

The JSON metadata references each array by its fixed path, byte size, and SHA-256
digest. Typed access checks every referenced payload. NPY arrays have no fixed
byte-size ceiling; readers check their dimensions against the HF record.

The read-only `HfOrbitals` enum carries distinct `RhfOrbitals` and
`UhfOrbitals` types for shared spatial orbitals and separate alpha/beta channels.
`UhfOrbitals::channels` uses `Spin<C>` and its shared payload save/load operations.
Their serialized descriptor layout is unchanged; only RHF and UHF are supported. Coefficients use column-major storage: rows retain the
original AO order, columns match orbital energies in Hartree, and occupied
orbitals form a prefix. The number of columns is the retained overlap rank,
which can be smaller than the AO row count. RHF occupied spatial orbitals carry
two electrons each; UHF channels carry one electron per occupied orbital.

Run the offline example from a checkout:

```sh
cargo run -p rustiq-chem-core --example persist_hf --no-default-features
```

The example writes into a temporary directory and verifies the restored RHF
coefficients and MP2 correlation energy. The API checks context identity, dimensions, occupations, finite
values, convergence metadata, and payload integrity on each typed access. These
checks do not independently establish physical validity or orbital orthonormality.
`hf_is_compatible` checks context compatibility without verifying the payload.
Reading the artifact alone does not construct an executable solution. To restore
one for MP2, the same calculation entry must also contain compatible AO ERIs.
The CLI `artifact verify` supports AO ERIs and converged RHF/UHF artifacts
through the typed Rust getters.

### Restoring a solution for MP2

The public `RestoreFromRustiQ` trait constructs an owned object from a
`RustiQData` entry. `RustiQData::restore::<T>()` delegates to that trait.
Converged `RhfSolution`, `UhfSolution`, and `AnyHfSolution` implement it:

```rust,ignore
use rustiq_core::{persistence::RustiQData, prelude::*};

# fn main() -> Result<(), Box<dyn std::error::Error>> {
let data = RustiQData::open("calculation.rustiq")?;
let hf: RhfSolution = data.restore()?;
// Equivalent: RhfSolution::restore_from_rustiq(&data)?
let mp2 = hf.mp2(Mp2Config::default())?;
println!("MP2 correlation energy: {} Hartree", mp2.correlation_energy);
# Ok(())
# }
```

Use `UhfSolution` for an unrestricted calculation. When the reference is selected
at runtime, restore `AnyHfSolution` and match its typed variants before calling
`.mp2()`:

```rust,ignore
let hf: AnyHfSolution = data.restore()?;
let mp2 = match hf {
    AnyHfSolution::Restricted(hf) => hf.mp2(Mp2Config::default())?,
    AnyHfSolution::Unrestricted(hf) => hf.mp2(Mp2Config::default())?,
    _ => return Err("unsupported HF reference".into()),
};
```

Restoration validates the HF artifact, its context, and the compatible AO ERI
payload. Missing, unsupported, incompatible, or corrupt required artifacts are
errors; requesting RHF from a UHF entry, or vice versa, also returns an error.
It does not run SCF or compute missing ERIs. It rebuilds the density from the
occupied orbitals and recomputes the kinetic and nuclear-attraction integrals
to reconstruct the energy decomposition. The electron-repulsion component is
the stored electronic energy minus the reconstructed kinetic and nuclear-attraction
components. Because final orbital and SCF densities can differ within the
convergence tolerance, these components can differ from the original summary.
Original HF energies and convergence diagnostics are retained; execution timings
are not persisted and are zero in
the restored summary. These checks trust the persisted convergence record;
they do not independently certify orbital canonicality or physical validity.

The restored solution owns its scientific data and remains usable after the
bundle is closed. Restoration does not modify the source. The offline
`persist_hf` example above saves both artifacts, reopens the bundle, restores
RHF, and compares the resulting MP2 correlation energy with the original
solution within `1e-12` Eh. It uses a temporary directory that is removed on
exit, closes the bundle before MP2, and prints HF total, MP2 correlation, and
MP2 total energies (HF total plus MP2 correlation). This checks the persistence
round trip for the bundled H2/STO-3G case, rather than independent scientific
accuracy. SCF/DIIS restart and automatic CLI HF capture/reuse remain future work.

The resolved context preserves effective normalized AO components and their
ordering. Original shell/contraction metadata is incomplete and must be added
before a Molden exporter can be implemented. See the
[HF artifact contract](https://github.com/mveril/RustiQ/blob/main/docs/persistence-format-v1.md#converged-hf-artifact-v1)
for the versioned representation and limits.

## Publication and failures

`--artifact` publishes the current requested collection; it does not append to
the source bundle. A new destination must not exist. An existing destination is
accepted only when it resolves to the explicit `--reuse` source, in which case
RustiQ replaces that bundle after producing a complete validated snapshot.
Other existing destinations are left untouched.

| Run outcome | Bundle behavior |
| --- | --- |
| Every requested calculation produces a result | Publish the current collection. |
| A preparation or execution error occurs | Do not publish; preserve any prior destination. |
| HF-only run reaches its iteration limit | Its result can still publish the AO ERIs. A single HF run returns exit code `3`; a batch with non-converged results and no execution errors publishes, then returns `3` if none converged or `4` if some succeeded. See the [CLI exit-code contract](../reference/cli.md). |
| MP2 was requested but HF did not converge | MP2 execution fails, so the collection is not published. |

JSON for a completed calculation or batch may already have been written when a
later publication error is reported. See the [CLI reference](../reference/cli.md#cache-and-portable-bundles)
for exact exit and publication behavior and the
[persistence V1 specification](https://github.com/mveril/RustiQ/blob/main/docs/persistence-format-v1.md)
for the archive contract and the [EZFIO comparison](https://github.com/mveril/RustiQ/blob/main/docs/persistence-format-v1.md#relationship-to-ezfio).


The generic SCF persistence entry point is `ScfSolution<M, Converged>::to_artifact`,
available when the method descriptor implements `PersistScf`. Its associated
`Artifact` selects the versioned storage contract and value type. Each method
owns its context identity, conversion and artifact validation; the generic layer
requires no common orbital layout, HF summary, or retained AO integrals.
RHF and UHF descriptors implement this contract using `ConvergedHfArtifact`.
`ConvergedHf::from_solution` is a runtime HF convenience adapter to the same path.

The generic NPY conversion handles owned nalgebra matrices with static or
dynamic dimensions. Its expected shape is `(rows, columns)`, and its writer
preserves both axes in Fortran order. The slice writer used for HF energies
emits `(n,)` instead.

Nalgebra `Vector` and `RowVector` types additionally accept one-dimensional
NPY arrays `(n,)`, taking their orientation from the target type. Two-dimensional
input must match the requested orientation exactly. General matrices, including
`DMatrix` with one row or column, always require an exact two-dimensional shape.
