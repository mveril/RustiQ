RustiQ Manual

Error messages and exit codes

When a command fails, read the message in your terminal. It may name a file, highlight an input value, or suggest a fix. If the message includes a code starting with rustiq::, search for that exact code on this page.

For example, rustiq::run::input_read_failed means RustiQ could not read the calculation input. If the message says the file was not found, check the file name and the directory you ran the command from. For rustiq::basis::missing_offline, follow the steps for making the basis available locally.

Check the exit code

The exit code is a number your shell receives when RustiQ finishes. It tells you how the command ended. The rustiq::… code identifies an individual problem and can help you decide what to check.

For example, with rustiq installed, run these commands in Bash or another POSIX shell from a directory where missing.toml does not exist:

status=0
rustiq run missing.toml || status=$?
printf 'Exit code: %s\n' "$status"

RustiQ prints rustiq::run::input_read_failed in the error message, and the last line printed by the example is Exit code: 1. The shell puts the status of the failed command in $?, so the example saves it immediately.

In PowerShell, save the native process status immediately:

rustiq run missing.toml
$status = $LASTEXITCODE
Write-Output "Exit code: $status"
Exit codeWhat it meansWhat to check
0The command completed successfully. Some commands allow skips.Read the report if you need to know which items were skipped.
1The command encountered an error.Read the message and look up its diagnostic code below.
2RustiQ rejected the command-line arguments.Run the command with --help to check its syntax and options.
3No requested calculation succeeded because Hartree–Fock did not converge.Review the Hartree–Fock convergence guidance.
4Some calculations or methods succeeded and others failed or did not converge.Review the individual outcomes before using the results.
5Strict bundle verification skipped some artifacts and found no failures among those it checked.Review the skipped entries before relying on the verification.

See the command-line reference for the detailed rules for batches and bundle verification. Post-SCF campaigns return 0 when at least one method succeeds and none fails, even with skips; 4 when successes coexist with failures; and 1 when none succeeds.

Find codes in JSON reports

When a JSON report is produced, failed calculations in a batch put the code in error.code and the explanation in error.message. In artifact verification reports, invalid entries carry code alongside the errors list. Older reports may omit these code fields. Post-SCF skipped and failed outcomes use diagnostic.code, with the explanation in diagnostic.message and optional diagnostic.help. Failures preserve specific codes and use rustiq::post_scf::failed only when no code is available.

These JSON additions are a beta.2 compatibility change within schema version 1. Updated schemas accept older reports; consumers validating new reports against older strict schemas may need to update their schemas. A command can write a JSON report and still return a nonzero exit code, so check both when scripting.

Look up a diagnostic code

Use the message and any highlighted input to narrow down the cause. If you ask for help, include the code, the full message, and the command you ran.
