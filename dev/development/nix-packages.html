RustiQ Manual

Nix packages and shells

The flake also exposes legacyPackages.<system>.cpuTarget, a function accepting an LLVM CPU name and returning a CPU-specific RustiQ package. See the installation guide for commands and portability considerations. The default package remains portable.

The packages below are declared in flake.nix. All four shells share Rust build essentials. rust adds Rust development tools; mini-pyscf adds the Python reference-test environment to the minimal Rust shell; full combines both extensions. nix develop selects full by default.

Use nix develop .#<shell> to enter a named shell. The direnv setup can select the same names with RUSTIQ_DEV_SHELL; see Development environments.

Other flake outputs

The flake also exposes nix build .#book to build this manual, nix build .#cargo-artifacts for cached Cargo dependency artifacts, and nix build .#pyscf-environment for the base PySCF environment. These are build outputs rather than development shells. The default package is the RustiQ CLI binary, available through nix build. Its online manual follows the Cargo version: a dev prerelease identifier selects development documentation; other versions select the matching versioned manual. No release flag is needed. See releasing.

Installed manual and completions

The default package includes manual pages for man rustiq and its subcommands, such as man rustiq-artifact-inspect. Every page links to the online book. The package also includes the complete offline HTML manual under share/doc/rustiq/manual/html, including local equation and diagram resources. From the repository root:

nix build
./result/bin/rustiq docs
./result/bin/rustiq docs --print-path

Use --web to open the online manual. Cargo-only installations use the online manual by default; see installation.

The package also installs Bash, Zsh, and Fish completions in the standard Nix locations. Shell discovery depends on your Nix profile and shell setup.

Nushell also loads the completion automatically at interactive startup when the profile exposes share/nushell/vendor/autoload through its data directories. On NixOS, enabling programs.nushell exposes share/nushell from the system profile. Other profiles may need their share directory in XDG_DATA_DIRS.

Nushell, PowerShell, and Elvish scripts are also provided under share/rustiq/completions/ for manual loading. From the repository root, build the package with nix build, then load the script in the matching shell:

use ./result/share/rustiq/completions/rustiq.nu *

. ./result/share/rustiq/completions/rustiq.ps1

source ./result/share/rustiq/completions/rustiq.elv

For persistent configuration, use the corresponding installed profile path instead of a checkout’s result link. PowerShell support registers native argument completion only.

Nix generates the files with a separate build tool and sets RUSTIQ_PACKAGING=true so both generators omit themselves from manuals and completions. The installed executable retains online but disables the Cargo features manpages and completions, so it does not offer generation commands or link their dependencies. Other packagers can set the same variable when generating assets for a binary built without those features. Nix checks build and test all features separately; package installation checks verify the installed assets and the absence of generator commands.
